# Earth Online 测试完成后的收尾与部署流程

## 1. 当前结论

目前主要功能已经完成手工测试，下一阶段建议按以下顺序推进：

1. 固定当前可用版本；
2. 补核心业务自动化测试；
3. 做错误处理、安全和配置收尾；
4. 准备 Docker Compose；
5. 在本机执行一次完整部署验收；
6. 再考虑服务器部署。

不建议现在直接跳到正式部署。当前后端只有基础的 Spring Boot 上下文测试，前端暂时没有自动化测试，先补关键路径测试可以降低后续修改造成旧功能损坏的风险。

## 2. 第一阶段：固定当前可用版本

### 操作

- 再确认一次关键功能能够正常使用。
- 查看 Git 修改内容，排除临时文件、密钥和构建产物。
- 创建一次阶段性提交，例如：`feat: complete core earth-online features`。
- 可选：创建标签，例如 `v0.1.0`。

### 验收清单

- 登录、注册和退出正常。
- 首页发布文字、事件类型、心情、标签和图片正常。
- 时间线排序、详情和删除正常。
- 未来信件封存和到期打开正常。
- 好友搜索、申请、删除、文字聊天和图片聊天正常。
- 年度总结能够读取旧结果并重新生成。
- MinIO 不可用时，登录和普通文字功能仍可使用。

## 3. 第二阶段：补核心自动化测试

自动化测试不需要一开始覆盖所有页面，优先保护最重要的数据和权限流程。

### 后端测试优先级

建议先测试：

1. 用户注册、密码加密和登录鉴权；
2. JWT 缺失、错误和过期时返回 401；
3. 事记新增、查询、排序和删除权限；
4. 未来信件到期前禁止打开、到期后允许打开；
5. 好友申请、接受、拒绝和删除；
6. 非好友不能发送聊天消息；
7. 聊天消息保存、查询和接收方推送；
8. 年度总结缓存、重新生成和 DeepSeek 异常处理；
9. MinIO 不可用时的降级逻辑。

### 前端测试优先级

建议引入 Vitest 和 Vue Test Utils，先测试：

- 登录过期只跳转一次，不产生重定向循环；
- 时间线按 `createdAt` 倒序排列；
- 年度页面默认选择今年并读取已保存总结；
- 聊天发送成功、失败和重试状态；
- 图片上传失败时显示友好提示；
- 未来信件是否可打开的判断。

### 日常验证命令

```powershell
# 前端构建
npm.cmd run build

# 后端测试
cd backend
.\mvnw.cmd test
```

### 完成标准

- 所有测试通过。
- 核心接口至少包含成功、权限不足、参数错误三类情况。
- 修复功能时能够先增加复现测试，再修改代码。

## 4. 第三阶段：错误处理与安全收尾

### 配置与密钥

- Git 中只能保留 `.env.example`，不能提交 `.env.local` 或真实密钥。
- 检查并更换曾在截图、日志或提交记录中暴露过的 DeepSeek、MinIO、数据库密钥。
- `JWT_SECRET` 使用固定的高强度随机值，不要在每次启动时改变。
- 生产环境数据库账号不要使用 `root`。

### 前后端错误处理

- 统一处理 400、401、403、404、409、413、429 和 500。
- 页面只显示中文友好提示，不直接显示 Java 异常信息。
- DeepSeek 超时或返回格式错误时，不覆盖已有年度总结。
- MinIO 不可用时允许文字功能继续工作，上传操作明确失败。
- WebSocket 断开后自动重连；聊天发送继续以 REST 落库、WebSocket 实时接收。

### 数据检查

- 确认所有用户数据接口都按当前登录用户隔离。
- 确认删除好友后不能继续查询对话或发送消息。
- 确认私有 MinIO 文件只能通过后端授权或短时效签名地址访问。
- 给数据库建立备份和恢复方案。

## 5. 第四阶段：Docker Compose

Docker 不会让代码修改变麻烦。推荐保留两种运行方式：

- 开发模式：Vue、Spring Boot 在 IDEA/终端直接运行，只用 Docker 启动 MySQL 和 MinIO；
- 验收/部署模式：Vue、Spring Boot、MySQL、MinIO 全部由 Docker Compose 启动。

这样日常开发仍然有热更新，只有准备验收或部署时才重建镜像。

### 需要准备的文件

- `web/Dockerfile`：构建 Vue，并用 Nginx 提供静态页面；
- `backend/Dockerfile`：构建并运行 Spring Boot JAR；
- `docker-compose.yml`：统一编排 Web、后端、MySQL、MinIO；
- `.env.docker.example`：只写变量名和示例值；
- Nginx 配置：转发 `/api` 和 `/ws/chat`，支持 WebSocket Upgrade。

### Compose 服务关系

```text
浏览器
  └─ Web/Nginx
      ├─ /api     → Spring Boot
      └─ /ws/chat → Spring Boot WebSocket
                     ├─ MySQL
                     ├─ MinIO
                     └─ DeepSeek API
```

### 注意事项

- 容器内不能用 `localhost` 访问其他容器，应使用服务名，例如 `mysql:3306`、`minio:9000`。
- MySQL 和 MinIO 必须挂载持久化卷。
- DeepSeek、JWT、数据库和 MinIO 密钥通过环境变量注入。
- 不把生产密钥写进 Dockerfile 或镜像。
- 增加健康检查，后端应在 MySQL 可用后启动。

## 6. 第五阶段：本机完整部署验收

### 建议流程

1. 备份当前数据库和 MinIO 数据。
2. 使用空数据库启动 Compose，验证系统能否从零运行。
3. 创建两个测试账号。
4. 完整走一遍注册、登录、事记、图片、未来信件、好友、聊天和年度总结。
5. 重启所有容器，确认数据库记录和图片没有丢失。
6. 暂停 MinIO，验证降级行为；恢复后验证上传。
7. 暂停后端，确认前端不会无限刷新或重定向。
8. 修改 JWT 后确认旧 Token 失效且页面只跳转一次。

### 完成标准

- 一条命令可以启动整个项目。
- 容器重启后数据仍然存在。
- WebSocket 经 Nginx 代理后仍可实时收消息。
- 日志中没有密钥、密码、JWT 或用户私密正文。
- 所有核心自动化测试和手工验收通过。

## 7. 第六阶段：服务器部署

正式部署前再补充：

- 域名与 HTTPS；
- 防火墙只开放 80/443，MySQL 和 MinIO 管理端口不直接暴露公网；
- 自动数据库备份；
- 日志轮转与磁盘空间监控；
- DeepSeek 调用次数限制和费用保护；
- 上传文件大小、类型和访问权限限制；
- 发布前备份与失败回滚流程。

## 8. 推荐立即执行的下一步

下一步先做“核心后端接口自动化测试”，从登录鉴权、事记权限、未来信件到期判断和聊天权限四组开始。完成后再加入前端 Vitest，最后编写 Dockerfile 和 Docker Compose。

建议每完成一个阶段，都执行一次前后端构建、更新本文件的验收状态并创建独立 Git 提交，避免测试补充、业务修改和部署配置混在同一次提交中。
