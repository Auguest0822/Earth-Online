# 07 DeepSeek 年度总结

## 填空题

### D1（★）密钥位置

纠正配置：前端的 `VITE_DEEPSEEK_API_KEY` 应改为后端环境变量 `___`，由后端通过 `Authorization: ___ <key>` 调用模型。

### D2（★）缓存键

年度总结缓存至少要同时按 `___` 和 `___` 唯一确定，不能只按年份缓存。

### D3（★）sourceHash

将参与总结的记录按稳定顺序序列化后计算摘要。新增、删除或修改记录后，新 Hash 与缓存 Hash `___` 时，旧总结标记为过期。

## 纠错题

### D4（★★）前端直连模型

```js
fetch('https://api.deepseek.com/chat/completions', {
  headers: { Authorization: `Bearer ${import.meta.env.VITE_DEEPSEEK_API_KEY}` }
})
```

说明安全问题，并画出正确调用链。

### D5（★★）错误覆盖缓存

代码在 AI 返回前先删除旧总结，解析失败后用户没有任何结果。重构生成流程，保证新结果完整校验并保存成功后才替换旧缓存。

## 编程题

### D6（★★）结构化解析

实现模型响应解析：去除可能的 Markdown 代码围栏，解析 JSON，校验标题、总结、情绪概览、亮点和未来寄语；字段缺失时返回统一错误，不能保存半成品。

### D7（★★★）并发生成

两个相同用户、相同年份的生成请求同时到达。设计数据库唯一约束或应用锁，避免产生重复缓存，并说明失败重试策略。
