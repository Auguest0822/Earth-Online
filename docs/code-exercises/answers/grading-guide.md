# 评分标准

## 单题评分

- 填空题：代码准确 70%，能解释原因 30%。只有术语没有可运行写法不得满分。
- 纠错题：定位问题 30%，正确修复 40%，说明风险和边界 30%。
- 编程题：接口契约 15%，核心实现 35%，权限与校验 20%，异常处理 10%，测试 10%，调用链讲解 10%。

## 一票否决型错误

出现以下错误时，相关题最高得分不超过 50%：

- 信任前端传来的用户 ID 作为数据权限依据；
- 返回密码或密码哈希；
- 把 DeepSeek、MinIO 密钥写入前端；
- RAG 查询所有用户数据；
- 文件上传没有类型和大小限制；
- 只隐藏按钮，不做后端鉴权；
- 将 AI 输出未经校验直接持久化。

## 综合题验收清单

1. 正常路径可运行；
2. 未登录请求被拒绝；
3. 用户数据相互隔离；
4. 参数边界有校验；
5. 外部服务失败有明确行为；
6. 前端没有重复提交或永久 loading；
7. 返回 DTO 不泄露内部字段；
8. 至少有一个成功测试和一个失败测试；
9. 能口头说清完整调用链。

## 模拟卷等级

- 90～100：能够独立完成项目级功能并答辩；
- 75～89：主链路掌握，需加强异常与安全；
- 60～74：能补代码，但跨层设计不稳；
- 60 以下：建议按章节重新完成基础与纠错题。
