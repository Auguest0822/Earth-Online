# 09 综合编程题

每题都要提交代码、接口示例、验证步骤和 2 分钟口头讲解稿。

## I1（★★★）事件类型筛选

给年度回忆增加可选 `eventType`。修改前端、DTO、Service 和 Repository，保证筛选仍受用户与年份边界约束。

## I2（★★★）重新生成确认

年度总结存在且未过期时，普通点击直接使用缓存；用户选择“重新生成”时二次确认并传 `regenerate=true`。处理按钮并发点击和 AI 超时。

## I3（★★★）事记图片编辑

编辑事记时允许保留旧图、删除旧图、添加新图。设计前后端数据结构和失败补偿，避免数据库失败后留下大量孤儿对象。

## I4（★★★）未来信到期开启

实现 `draft → sealed → opened` 状态流转。草稿不能开启，未到期不能开启，已开启不能再次封存。前后端都要提示，但后端是最终规则执行者。

## I5（★★★）聊天幂等

客户端断线重连可能重复发送。使用 `clientMessageId` 与数据库唯一约束保证消息只保存一次，并通过 WebSocket 返回最终服务端消息。

## I6（★★★）服务降级

分别模拟 MinIO、DeepSeek 和后端不可用。要求文字资料不因 MinIO 失败而消失；旧年度总结不因 DeepSeek 失败被覆盖；前端对网络错误提供重试。

## I7（★★★）用户数据导出

新增导出当前用户生活事记的 JSON 接口。不得导出密码哈希、其他用户数据或永久图片公开地址；大数据量使用流式或分页方案。

## I8（★★★）安全代码审查

检查一条完整链路：登录 → 新增事记 → 上传图片 → 年度总结 → RAG。提交至少 8 个安全或健壮性检查点，并为其中 3 个补自动化测试。
