# 01 项目启动与前端骨架

## 总体调用关系

```text
浏览器
  → Vue 3 页面 / Router / Pinia
  → httpClient（REST）或 chatSocket（STOMP）
  → Spring Boot Controller
  → Service
  → JPA Repository / MySQL
  → MinIO 或 DeepSeek（需要时）
```

## Vue 应用入口

项目入口是 `web/src/main.js`。典型启动过程可以理解为：创建 Vue 应用，安装 Router、Pinia 和 Element Plus，最后挂载到 `index.html` 的 `#app`。

```js
const app = createApp(App) // 创建根应用，App.vue 是根组件
app.use(pinia)             // 注册全局状态容器
app.use(router)            // 注册官方路由
app.use(ElementPlus)       // 注册 UI 组件库
app.mount('#app')          // Vue 接管页面中的 #app 节点
```

`use` 是插件安装机制；`mount` 才真正开始渲染。顺序上应在挂载前安装插件，否则组件中无法正常使用路由或 Store。

## Router 逐段旁注

真实代码位于 `web/src/router/index.js`：

```js
const router = createRouter({
  history: createWebHistory(import.meta.env.BASE_URL),
  routes: [
    {
      path: '/timeline',
      name: 'timeline',
      component: () => import('../views/TimelineView.vue'),
      meta: { requiresAuth: true }
    }
  ]
})
```

- `createWebHistory` 使用 History API，URL 没有 `#`。
- `name` 便于编程式跳转，路径调整时不用到处修改字符串。
- `() => import(...)` 是路由懒加载；访问该页面时才下载对应代码块。
- `meta.requiresAuth` 是项目约定的路由元数据，供全局守卫判断。

```js
router.beforeEach((to) => {
  const token = getAccessToken()

  if (to.meta.requiresAuth && !token) {
    return { name: 'login' }
  }

  if (to.name === 'login' && token) {
    return { name: 'home' }
  }
})
```

- `beforeEach` 在每次导航前执行。
- `to` 是目标路由；返回路由对象表示重定向，不返回表示继续。
- 这里只判断浏览器是否保存 Token，不证明 Token 一定合法。
- Token 伪造、过期或被撤销后，仍要由后端鉴权。

## Vite 开发代理

`web/vite.config.js` 将浏览器的 `/api` 转发到 8080，将 `/ws` 转发为 WebSocket：

```js
server: {
  proxy: {
    '/api': { target: 'http://localhost:8080', changeOrigin: true },
    '/ws': { target: 'ws://localhost:8080', ws: true, changeOrigin: true }
  }
}
```

这样前端不必硬编码完整地址，也避免开发环境跨域。它只在 Vite 开发服务器中生效，生产环境需要由 Nginx、网关或同源部署承担转发。

## 评委可能追问

**为什么用路由懒加载？** 首屏只加载当前页面需要的代码，降低初始包体积；项目的各业务页面可按路由拆包。

**前端守卫能保证安全吗？** 不能。用户可以绕过页面直接请求 API，后端必须验证 JWT，并按当前用户限制数据库查询。

**刷新子路由为什么可能 404？** History 模式下服务器要把未知前端路径回退到 `index.html`，再交给 Vue Router 解析。
