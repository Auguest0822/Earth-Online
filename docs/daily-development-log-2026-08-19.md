# 开发记录：好友模块与真实数据对接（2026-08-19）

## 今日目标

完成“通过 10 位地球 ID 添加好友”的基本流程，并让朋友页面优先展示后端真实数据，为下一步的聊天功能做准备。

## 已完成的功能

### 1. 为用户增加公开地球 ID

- 在 `users` 表中增加 `public_id` 字段。
- 每个用户拥有一个唯一的 10 位数字 ID。
- 旧账号也补齐了 ID，因此不需要重新注册。
- 注册新账号时，后端会自动生成一个尚未被使用的 10 位 ID。

为什么不用用户名作为好友搜索依据：用户名可能被用户修改，也可能包含不便输入的字符；公开地球 ID 专门用于分享和搜索，稳定且更适合好友系统。

### 2. 个人资料展示公开地球 ID

“我的地球档案”中会显示用户自己的 10 位地球 ID，用户可将它提供给朋友进行搜索。

### 3. 好友申请后端流程

实现的流程如下：

```text
搜索对方公开 ID
    ↓
发送好友申请（PENDING）
    ↓
对方查看收到的申请
    ↓
接受（ACCEPTED）或拒绝
    ↓
双方进入好友列表
```

主要接口：

| 功能 | 接口 |
| --- | --- |
| 根据地球 ID 搜索用户 | `GET /api/friends/search?publicId=xxxxxxxxxx` |
| 发送申请 | `POST /api/friends/requests` |
| 查看收到的申请 | `GET /api/friends/requests/received` |
| 接受申请 | `POST /api/friends/requests/{id}/accept` |
| 拒绝申请 | `POST /api/friends/requests/{id}/reject` |
| 获取好友列表 | `GET /api/friends` |

所有接口均要求携带 JWT：

```http
Authorization: Bearer <accessToken>
```

后端根据 Token 识别当前用户，因此前端不能自行传入“我是谁”的用户 ID。

### 4. 朋友页面接入真实 API

朋友页面完成了以下真实数据展示：

- 好友数量；
- 按 10 位地球 ID 搜索未添加用户；
- 搜索结果及申请状态；
- 收到的好友申请；
- 接受、拒绝申请；
- 已添加好友列表；
- 好友头像、用户名、地球 ID 和个性签名。

收到的好友申请数量徽标使用红色，表示“待处理提醒”。

### 5. 非新闻页面统一使用真实 API

项目的数据源规则调整为：

- 新闻页面：保留 Mock / 聚合数据 / GNews 的独立切换能力，便于调试第三方新闻服务；
- 其他页面：默认并固定使用 Spring Boot 后端 API；
- 头像、用户名、记录、未来信件、个人资料、好友信息都应来自 MySQL 和 MinIO，而不是前端演示数据。

说明：当用户没有上传头像时，界面可以显示默认占位头像；这只是视觉占位，不代表使用了 Mock 用户数据。

## 今日遇到的问题与处理

### 问题 1：好友搜索返回 400 或 404

原因：测试时把“对方的 10 位地球 ID”当作文字直接传入，或输入的 ID 不存在；另外 URL 参数中存在多余空格也会导致校验失败。

处理方式：

- 从数据库或个人档案复制准确的 10 位 `public_id`；
- 请求参数只保留数字，例如 `publicId=8431239264`；
- 不要在等号后加入空格。

### 问题 2：好友已接受，但朋友页提示 `No static resource api/chat/messages`

原因：前端已经尝试加载聊天记录，但正在运行的后端进程仍是旧版本，没有加载聊天 Controller，Spring Boot 便把该 URL 当作静态资源查找并返回 404。

处理方式：

1. 在 IDEA 执行 **构建 → 重新构建项目**；
2. 停止旧的 `BackendApplication`；
3. 重新启动后端；
4. 确认日志出现 `Tomcat started on port 8080` 和 `Started BackendApplication`；
5. 用新登录获得的 Token 再测试聊天接口。

聊天接口在没有消息时应返回空数组 `[]`，这不是错误。

### 问题 3：朋友页面出现旧的头像或用户名

原因：浏览器 localStorage 中可能保留旧的用户缓存，或页面仍使用了原先的 Mock 数据源设置。

处理方式：

- 登录成功后以 `/api/auth/me` 返回的用户信息更新本地状态；
- 登出时清理 Token 和用户缓存；
- 修改数据源配置后刷新页面，必要时使用 `Ctrl + F5` 强制刷新；
- 非新闻页面不应在 API 请求失败时回退为 Mock 用户。

## 下一步：实现好友聊天

下一阶段的目标是让已互为好友的两个用户可以发送文字消息。

第一版范围：

1. `GET /api/chat/messages?friendPublicId=...` 获取双方聊天记录；
2. `POST /api/chat/messages` 发送文字消息；
3. 将消息存入 MySQL 的 `chat_messages` 表；
4. 前端发送后立即刷新消息列表；
5. 空聊天显示“还没有聊天记录，和好友打个招呼吧”。

暂不实现 WebSocket 实时推送、语音、撤回、已读状态和群聊；这些可以在文字聊天稳定后再扩展。
