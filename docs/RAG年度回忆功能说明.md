# RAG 年度回忆功能说明

## 功能定位

年度记录页保留原有统计图表和年度总结，并增加“问问这一年”功能。用户选择具体年份后，可以用自然语言回顾个人记录，系统返回回答以及作为依据的原始记录。

## 第一版实现方式

当前采用轻量混合检索，不依赖向量数据库：

1. 后端从 JWT 登录身份取得当前用户，不能由前端指定用户 ID；
2. 使用当前用户 ID 和所选年份查询候选记录；
3. 根据问题与记录标题、正文、关键词、事件类型、心情的匹配程度计算相关度；
4. 取最多 5 条相关记录，宽泛问题匹配不足时以该年近期记录补足上下文；
5. 只将检索结果和问题发送给 DeepSeek，要求模型不得使用记录外的事实；
6. 返回答案及记录 ID、标题、日期和正文摘要，前端可跳转查看原记录。

因此，该功能已经具备 RAG 的“检索、增强上下文、生成、来源引用”完整链路，但不应描述为“向量 RAG”。数据规模扩大后，可将第 3 步替换为 Embedding 和向量相似度检索，页面与接口结构无需大改。

## 页面交互

- “年度总结”默认展示摘要、年度亮点和关键词，情绪概览与写给未来的话可以展开；
- “问问这一年”提供问题输入框和推荐问题；
- 回答生成期间显示“正在翻阅与你问题相关的记录”；
- 每次回答显示引用记录，点击后进入时间线并打开对应记录；
- 切换年份会清空旧回答，防止不同年份的内容混淆；
- 没有记录、未选择年份、AI 未配置或调用失败时，仅影响 AI 区域，不影响年度图表。

## 接口

`POST /api/ai/yearly-memory/query`

请求示例：

```json
{
  "year": 2026,
  "question": "这一年有哪些让我开心的事情？"
}
```

响应示例：

```json
{
  "question": "这一年有哪些让我开心的事情？",
  "answer": "从现有记录来看……",
  "year": 2026,
  "sources": [
    {
      "recordId": 12,
      "title": "和朋友见面",
      "date": "2026-08-19",
      "excerpt": "今天和很久没见的朋友……",
      "score": 0.83
    }
  ]
}
```

## 答辩表述

> 年度总结解决的是“系统主动概括整年”，RAG 问答解决的是“用户针对这一年自由追问”。后端先通过当前用户和年份隔离数据，再进行轻量混合检索，只把最相关的记录交给 DeepSeek，并把来源记录随答案返回，从而减少无依据生成并保护用户数据边界。

## 后续升级

- 为记录生成 Embedding，并使用向量数据库或支持向量类型的数据库进行语义检索；
- 将关键词匹配分数与向量相似度组合成混合排序；
- 增加问答频率限制、结果缓存和调用费用统计；
- 建立“答案是否被引用记录支持”的自动化评测集。
